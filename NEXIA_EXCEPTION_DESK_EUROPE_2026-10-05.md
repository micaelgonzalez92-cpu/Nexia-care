# European Exception Desk — competitive refresh — 2026-10-05

## Classification
HECHO VERIFICADO: public 2026 sources show repeated accounting document-collection/chasing products and workflows across Europe/UK.
ESTIMACIÓN: the generic collection layer is increasingly commoditized.
HIPÓTESIS: the better low-capital wedge is a managed exception-control layer that sits above existing portals/tools.
RECOMENDACIÓN: do not build collection software before a buyer confirms an unresolved exception problem.

## New evidence
- Alkmist describes secure accounting onboarding as templated requests + portal + automated follow-up + validation + blocked-state tracking. This confirms the basic workflow is already productized.
- DBes describes a delivered UK accounting portal replacing email chasing with checklists, reminders and audit trail.
- BilagPilot's August 2026 comparison lists multiple categories: transaction-aware chasing, general collection, native Xero/QuickBooks requests, and adjacent practice-management/capture tools.
- Fabren explicitly recommends human approval for client-facing sends and close-impact decisions. This supports the human-in-the-loop architecture but is vendor guidance, not independent validation.
- Doxalio's September 2026 workflow frames the unresolved end of reconciliation as the costly part: unexplained bank lines require a document or an explicit reason.
- Expensent focuses on the pre-accounting receipt gap in client inboxes, further showing the market is fragmenting around specific exception points.

## Strategic adjustment
The product should not own the document portal. It should own the exception queue.

Potential wedge:
existing systems -> exception detection -> close-impact ranking -> owner/next action -> human approval -> evidence trail

First commercial ICP to test:
small accounting/bookkeeping firms with recurring month-end close work and existing portal/accounting software.

First buyer conversation should ask only about:
1. what repeatedly blocks a close;
2. how exceptions are currently tracked;
3. which exceptions are invisible until too late;
4. how much staff time is spent reconstructing status;
5. whether a human-approved exception queue would be useful.

No pricing claim is made yet.

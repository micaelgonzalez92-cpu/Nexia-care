# NEXIA — INDEPENDENCE ROADMAP

Updated: 2026-10-05
Status: ACTIVE / ZERO-COST PLANNING

## Objective
Move NEXIA from a ChatGPT-dependent operating surface toward an independent product/system without losing continuity, evidence, guardrails or economic discipline.

## Current verified state
- Persistent project anchor: GitHub repository.
- Clean product routes exist: /NexaCare/ and /NexaHQ/.
- GitHub Pages hostname still exposes the hosting account identity.
- Public runtime verification is still pending.
- Floot is not recovered and is not required for continuity.
- Telemetry and notifications are not connected.
- Autonomous execution is partial through scheduled automations.
- Real user evidence: 0.
- Revenue: €0.
- Spend: €0.

## Target architecture
PUBLIC USERS
→ NexaCare
→ diagnostic/evidence layer
→ persistent data store
→ NEXIA CORE
→ mission/evidence/economics engines
→ NexaHQ
→ authenticated Kael control plane

NEXIA CORE must not depend on a ChatGPT conversation as its source of truth.

## Independence levels

### L1 — Continuity independent
DONE IN DESIGN:
- persistent state
- recovery documents
- session bootstrap
- replaceable ChatGPT/Floot surfaces

### L2 — Public identity independent
PARTIAL:
- NexaCare/NexaHQ routes implemented
- remaining blocker: custom domain or different hosting identity

### L3 — Runtime independent
PENDING:
- hosted application runtime
- persistent database
- authenticated control plane
- server-side business logic

### L4 — Operationally independent
PENDING:
- telemetry
- event ingestion
- automated evidence capture
- reliable notifications
- scheduled jobs outside ChatGPT
- audit trail

### L5 — Commercially independent
PENDING:
- first real user evidence
- validated offer
- first real extraction
- reproducible extraction
- positive unit economics

### L6 — Autonomous machine
PENDING:
- repeatable opportunity discovery
- acquisition
- diagnosis/decision engine
- transaction layer
- monitoring
- safe autonomous optimisation
- human gates only for money, external commitments, irreversible actions and material risk

## Order of execution
1. Protect continuity and remove stale documentation.
2. Verify NexaCare/NexaHQ public runtime.
3. Choose zero-cost hosting/runtime path for L3.
4. Define persistent data model and event/audit model.
5. Separate public UI from authenticated control plane.
6. Connect telemetry and notifications.
7. Obtain real NEXIA Care users.
8. Validate economics.
9. Execute first extraction only after Human Gate.
10. Repeat and automate.
11. Introduce custom domain when it has clear value and approved cost.
12. Reduce ChatGPT to an optional interface rather than the system itself.

## Human Gate
Requires Kael:
- buying a domain
- paid hosting/services
- external account creation where authorization is required
- external contact
- publication/deletion with material consequences
- credentials/secrets
- security changes with material risk
- commercial commitments

## Principle
NEXIA does not become independent by merely moving the UI outside ChatGPT.
Independence means the state, runtime, data, jobs, authentication, telemetry and business loop can operate without this conversation.

## Next safe mission
Verify public runtime and continue zero-cost work toward L3 while keeping EXP-001B as the commercial validation bottleneck.

# NEXIA MEMORY — Banco de Aprendizaje

## Purpose
Acumular evidencia y aprendizaje operativo para evitar repetir experimentos, separar señales de evidencia y mejorar NEXIA Care.

## Experiment schema
- ID
- Hypothesis
- Action
- Cost
- Metrics
- Success criterion
- Failure criterion
- Result
- Learning
- New question
- Next action
- Reproducibility status

## Current experiment
### EXP-001B — Prueba de diagnóstico con usuario real
- Hypothesis: una persona sin conocimientos técnicos puede completar el diagnóstico de NEXIA Care y llegar a una acción útil de forma autónoma.
- Action: prueba con una persona real y cafetera compatible, preferiblemente De'Longhi Magnifica; observar sin sobreayudar.
- Cost: 0 €
- Primary metric: porcentaje que llega a una recomendación útil.
- Secondary metrics: tiempo, abandonos, puntos de duda, preguntas y valoración de utilidad.
- Success: completa el flujo y entiende qué acción tomar sin asistencia significativa.
- Failure: necesita ayuda, abandona o no entiende/confía en el resultado.
- Result: pendiente de prueba real.
- Learning: pendiente.
- New question: ¿qué partes del flujo generan fricción o confianza?
- Next action: conseguir primera prueba real.
- Reproducibility: no evaluable hasta disponer de resultados repetidos.

## Ideas de mejora acumuladas
1. Mission Generator: Radar → Señal → Investigación → Veta → Validación → Experimento → Resultado → Aprendizaje → Nueva misión.
2. Learning loop: cada experimento debe producir un cambio, una decisión o un descarte.
3. Evidence ledger: separar HECHO VERIFICADO / ESTIMACIÓN / HIPÓTESIS / RECOMENDACIÓN.
4. Experiment guardrails: coste máximo, riesgo, métrica, éxito y fracaso antes de ejecutar.
5. Command Deck: Seguir, Pausar, Parar, Informe, Economía, Misión actual, Mis tareas, Mapa, Investigación y Experimento.
6. Financial engine: ingresos → costes → impuestos → beneficio neto → reserva/reinversión.
7. Reproducibility gate: una extracción solo cuenta como reproducible cuando el proceso puede repetirse con resultados económicos reales.
8. Opportunity memory: registrar oportunidades descartadas y motivo para no investigarlas de nuevo sin nueva evidencia.
9. User-test engine: preparar guiones, registrar observaciones y convertir patrones de usuarios en tickets de mejora.
10. Agent scoreboard: medir cada agente por evidencia generada, coste evitado, experimentos útiles y falsos positivos.
11. Autonomous queue: cola priorizada de tareas que puedan ejecutarse sin intervención humana dentro de límites autorizados.
12. Human decision gate: cualquier gasto, riesgo importante o escalado queda bloqueado hasta aprobación explícita de Kael.
13. Regression checks: cada cambio de NEXIA Care debe conservar los flujos de diagnóstico que ya funcionan.
14. Product discovery loop: problemas reales → diagnóstico → solución → intención de compra → economía unitaria → experimento comercial.
15. Anti-loop detector: detectar investigaciones repetidas, hipótesis antiguas y tareas sin aprendizaje.
16. Mission rewards: XP solo por evidencia y resultados, no por actividad.
17. 24/7 architecture: automatizaciones programadas + agentes + colas + monitorización; no asumir que el chat trabaja en segundo plano.
18. Zero-cost-first: priorizar investigación, código, pruebas y aprendizaje sin gasto antes de usar capital.
19. Opportunity scoring without vanity metrics: priorizar por demanda, margen potencial, facilidad de validación, riesgo y coste de aprendizaje.
20. Post-mortem automático: cada experimento cerrado debe producir conclusión, descarte o siguiente misión.

# NEXIA GAME SYSTEM — v0.1

## Purpose
Convert NEXIA from a static dashboard into a business strategy game where progression is earned by evidence and economic results.

## Core rule
No XP, level-up, unlock or victory is awarded for document count, conversation count or visual complexity.

Progress requires:
1. Evidence
2. Result
3. Learning
4. Reproducible improvement

## Player
- Commander: Kael
- System: NEXIA
- Role split: NEXIA discovers, analyses, validates and executes safe no-spend work; Kael decides spending, major risk, commitments and scaling.

## Levels
### Level 1 — OBSERVE
Collect signals without spending.

### Level 2 — ANALYSE
Filter signals, estimate economics and identify falsification paths.

### Level 3 — VALIDATE
Run safe experiments and obtain real-world evidence.

### Level 4 — EXTRACT
Achieve the first real economic result.

### Level 5 — REPEAT
Reproduce the extraction through a defined process.

### Level 6 — SCALE
Increase volume without breaking unit economics or risk controls.

### Level 7 — COMPOUND
Use memory, automation and repeated learning to improve the machine itself.

## XP policy
XP sources:
- + evidence from real behaviour
- + completed experiment
- + falsified hypothesis
- + validated economics
- + first transaction
- + repeatable transaction
- + measurable automation
- + reduction in human time
- + reproducible improvement

XP does NOT come from:
- documentation alone
- UI changes alone
- speculative opportunities
- unverified revenue
- simulated users
- invented metrics

## Technology tree

### RESEARCH
Radar → Signal clustering → Opportunity mining → Trend detection

### VALIDATION
Experiments → Human sensors → Confidence engine → Falsification engine

### ECONOMY
Unit economics → Pricing → Margin control → Profit engine

### AUTOMATION
Agents → Memory → Safe execution → Mission queue

### SCALE
Acquisition → Conversion → Retention → Replication

### COMPOUNDING
Learning loop → Agent improvement → Process compression → Autonomous opportunity pipeline

## Mission states
RUMOR → SIGNAL → VETA → VALIDATED → EXTRACTION → REFINED → SCALABLE

A mission cannot skip evidence gates.

## Event engine
Events should be generated from real state changes where possible:
- new evidence
- experiment completed
- blocker detected
- opportunity strengthened
- opportunity falsified
- human gate required
- extraction achieved
- reproducibility achieved

## Human Gate
Required for:
- spending
- buying inventory
- hiring
- debt
- important external commitments
- irreversible publication
- material risk
- scaling after validation
